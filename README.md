# Hoopi Mobile

Hoopi Mobile is the native React Native companion to Hoopi. It connects to the Hoopi API and gives users a mobile-first way to chat with Hoopi, delegate work, manage reference knowledge, and access workspace files. The app uses Expo and Expo Router; it is not a WebView wrapper around the website.

## What the app does

- **Chat:** Send prompts to Hoopi in chat or work mode, stream assistant replies, render Markdown, and reopen recent conversations. Read assistant replies aloud, dictate a draft, or start a live voice conversation when enabled by the platform administrator.
- **Tasks:** Manage workspace boards, tasks, subtasks, people, agents, due dates, priorities, labels, and custom fields. Review agent questions and results, use board templates, or plan a board with AI. The existing Work activity screen is available inside Tasks.
- **Knowledge:** Upload reference documents and follow their indexing status.
- **Files:** Browse, upload, and download workspace files, including files generated by Hoopi.
- **Account and workspaces:** Sign in or register, view account details, switch workspaces, and sign out.

The app currently uses `https://api.hoopi.ai` as its backend. The UI uses a warm editorial palette, bundled Lora headings, and native botanical accents and uses native navigation, forms, lists, and device document selection.

## Tech stack

- Expo SDK 58 and React Native 0.88
- TypeScript and Expo Router
- gluestack-ui v3 components, NativeWind v4, and Tailwind CSS v3 for the UI
- Reanimated for native motion
- Expo SecureStore for access tokens and selected workspace state
- Expo Document Picker for file selection
- `react-native-markdown-display` for assistant message formatting
- Expo Speech for read-aloud playback and Expo Speech Recognition for native dictation

## Development setup

### Requirements

- Node.js and npm
- Expo Go on a physical device, or an Android/iOS simulator
- Network access to `https://api.hoopi.ai` and a Hoopi account for authenticated features

### Install and start

Run these commands from this directory (`mobile/`):

```bash
npm install
npx expo start
```

Scan the terminal QR code with Expo Go to open the app on a device. Keep the phone and development machine on a network that can reach the Metro server. To launch an available Android or iOS simulator directly, use:

```bash
npx expo start --android
npx expo start --ios
```

For a clean Metro cache after dependency or bundler changes:

```bash
npx expo start --clear
```

The Expo Go version needs to support this project's SDK. For behavior that requires a custom native development client, create an Expo development build.

Voice input and live voice mode require a rebuilt native app and are unavailable in Expo Go. See the [speech guide](docs/speech.md) for dictation/read-aloud setup and the [live voice guide](docs/voice-mode.md) for call setup and verification; read aloud works in the matching Expo Go SDK.

## Configuration

- **Backend URL:** `src/lib/api.ts` exports `API_BASE_URL` (`https://api.hoopi.ai`). Change it there when targeting another API environment. There are no API secrets in the mobile app; do not add private credentials to client code.
- **Android application ID:** `app.json` uses `com.saqibvizzexpodevsteam.hoopimobile`. Keep this identifier stable after distributing builds so Android can recognize upgrades to the same app.
- **EAS project:** The EAS project ID is stored in `app.json`; build profiles are in `eas.json`.
- **Brand styles:** Tokens are in `src/constants/design.ts`, gluestack components in `src/components/ui/`, and branded wrappers in `src/components/ui.tsx`. See [the UI system guide](docs/ui-system.md).

Authentication stores the access token and selected workspace with SecureStore. API requests include the token and workspace ID; the API client also handles token refresh and clears the session when it expires. Chat responses arrive as a server-sent event stream.

### Adding or changing screens

- Add Expo Router screens under `src/app/`; route groups in parentheses organize screens without changing their URL paths.
- The main tab navigator and tab labels are in `src/app/(tabs)/_layout.tsx`.
- Use gluestack components from `src/components/ui/` and branded controls from `src/components/ui.tsx`. Shared colors belong in `src/constants/design.ts`. Keep screen-specific behavior in its route or a focused component.
- Use native React Native and Expo APIs for mobile experiences instead of embedding the website.
- When adding Expo or React Native dependencies, use `npx expo install <package>` to select a version compatible with the project's SDK.
- Run lint and TypeScript checks before committing changes.

Expo generates native projects when needed. Keep generated `android/` and `ios/` folders out of source control; configure native behavior through Expo config and plugins unless this project intentionally moves to a prebuild/native workflow.

## Tasks module

Tasks is the second bottom tab. Open **Work activity** from its home screen for the existing agent activity feed. Boards belong to the selected workspace and use the same `/api/v1/task-boards`, `/tasks`, question, approval, and agent APIs as the web app.

- **Views:** grouped task list, status board, due-date calendar, a six-week timeline with earlier/later navigation, and a progress dashboard. Search and filters apply across views.
- **Native interaction:** long-press a task title in Board view to reorder within its status. Tap its status to move it to another status. Reordering is disabled while filtering, selecting, or viewing archived tasks. Subtasks stay with their parent and open from the task detail screen.
- **Editing:** task descriptions, Markdown results and comments, multiple people and agents, labels, priorities, due dates, and text/number/date/label/People custom fields. Assigning agents can start backend work; reviewing results and answering questions always require an explicit action.
- **Organization:** edit/reorder board statuses, groups, fields and priorities; archive/restore boards and tasks; select multiple tasks for bulk changes or CSV sharing. Partial bulk failures remain selected for retry. Permanent deletion follows backend permissions and asks for confirmation.
- **Templates:** preview built-in templates, create/edit workspace templates, duplicate a template, save a board as a template, and create a board from a saved template. Template edits must be saved before using them to create a board.
- **AI planner:** uses the existing streamed chat endpoint and web planner prompt, with a separate conversation and the initiating workspace pinned for the entire request. Stopping a response does not undo changes the backend already saved.

The module reuses [TanStack Query](https://tanstack.com/query/latest/docs/framework/react/react-native) for server state, [Gorhom Bottom Sheet](https://gorhom.dev/react-native-bottom-sheet/) for pickers and forms, [Wix React Native Calendars](https://github.com/wix/react-native-calendars) for calendars, and [Draggable FlatList](https://github.com/computerjazz/react-native-draggable-flatlist) for reordering. Dates use the [native date picker](https://docs.expo.dev/versions/v58.0.0/sdk/date-time-picker/); CSV files use [Expo FileSystem](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/) and [Expo Sharing](https://docs.expo.dev/versions/v58.0.0/sdk/sharing/).

Queries are scoped by workspace, pause when the app or screen is inactive, and refresh after changes. Boards and task results poll while agents are active; the attention queue polls while its screen is active. Requests keep their original workspace even if the user switches workspaces during a save.

After installing these dependencies, rebuild an existing development client or APK to include the date picker and sharing modules. A matching SDK 58 Expo Go includes these modules, but the app's voice input/live voice features still require a native build. Use a physical Android and iOS device to check date dialogs, keyboard avoidance, drag gestures, sheet dismissal, back navigation, and the system share sheet before distributing a release.

## Build an Android APK

EAS Build produces the installable Android APK in the Expo cloud using the `preview` profile:

```bash
eas build --platform android --profile preview
```

See [docs/android-apk-build.md](docs/android-apk-build.md) for EAS account requirements, installation instructions, and the distinction between APK testing builds and Play Store AAB builds.

## Build for iOS

First, register your iOS device with EAS:

```bash
eas device:create
```

Then create an iOS build using the `preview` profile:

```bash
eas build --platform ios --profile preview
```
