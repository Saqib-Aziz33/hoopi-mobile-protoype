# Hoopi Mobile

Hoopi Mobile is the native React Native companion to Hoopi. It connects to the Hoopi API and gives users a mobile-first way to chat with Hoopi, delegate work, manage reference knowledge, and access workspace files. The app uses Expo and Expo Router; it is not a WebView wrapper around the website.

## What the app does

- **Chat:** Send prompts to Hoopi in chat or work mode, stream assistant replies, render Markdown, and reopen recent conversations.
- **Work:** Review agent activity, status, and result summaries; start a task in work mode.
- **Knowledge:** Upload reference documents and follow their indexing status.
- **Files:** Browse, upload, and download workspace files, including files generated by Hoopi.
- **Account and workspaces:** Sign in or register, view account details, switch workspaces, and sign out.

The app currently uses `https://api.hoopi.ai` as its backend. The UI follows Hoopi's violet, blue, and cyan brand colors and uses native navigation, forms, lists, and device document selection.

## Tech stack

- Expo SDK 58 and React Native 0.88
- TypeScript and Expo Router
- Reanimated for native motion
- Expo SecureStore for access tokens and selected workspace state
- Expo Document Picker for file selection
- `react-native-markdown-display` for assistant message formatting

## Development setup

### Requirements

- Node.js and npm
- Expo Go on a physical device, or an Android/iOS simulator
- Network access to `https://api.hoopi.ai` and a Hoopi account for authenticated features

### Install and start

Run these commands from this directory (`mobile/`):

```bash
npm install
npx expo start
```

Scan the terminal QR code with Expo Go to open the app on a device. Keep the phone and development machine on a network that can reach the Metro server. To launch an available Android or iOS simulator directly, use:

```bash
npx expo start --android
npx expo start --ios
```

For a clean Metro cache after dependency or bundler changes:

```bash
npx expo start --clear
```

The Expo Go version needs to support this project's SDK. For behavior that requires a custom native development client, create an Expo development build.

## Configuration

- **Backend URL:** `src/lib/api.ts` exports `API_BASE_URL` (`https://api.hoopi.ai`). Change it there when targeting another API environment. There are no API secrets in the mobile app; do not add private credentials to client code.
- **Android application ID:** `app.json` uses `com.saqibvizzexpodevsteam.hoopimobile`. Keep this identifier stable after distributing builds so Android can recognize upgrades to the same app.
- **EAS project:** The EAS project ID is stored in `app.json`; build profiles are in `eas.json`.
- **Brand styles:** Shared colors and UI primitives are in `src/components/ui.tsx`. Chat Markdown styles are in `src/components/chat-message.tsx`.

Authentication stores the access token and selected workspace with SecureStore. API requests include the token and workspace ID; the API client also handles token refresh and clears the session when it expires. Chat responses arrive as a server-sent event stream.

## Project layout

```text
src/
  app/                 Expo Router routes and layouts
    (tabs)/            Chat, Work, Knowledge, Files, and You screens
    login.tsx          Sign-in screen
    register.tsx       Account registration screen
  components/          Shared UI, chat message, and helper components
  constants/           Theme constants
  context/             Authentication and user session state
  hooks/               Theme and color-scheme hooks
  lib/api.ts           API client, auth, uploads, and chat streaming
assets/                App icons, mark, and bundled images
docs/                  Additional guides, including EAS APK builds
```

### Adding or changing screens

- Add Expo Router screens under `src/app/`; route groups in parentheses organize screens without changing their URL paths.
- The main tab navigator and tab labels are in `src/app/(tabs)/_layout.tsx`.
- Shared controls and Hoopi colors belong in `src/components/ui.tsx`; keep screen-specific behavior in its route or a focused component.
- Use native React Native and Expo APIs for mobile experiences instead of embedding the website.
- When adding Expo or React Native dependencies, use `npx expo install <package>` to select a version compatible with the project's SDK.
- Run lint and TypeScript checks before committing changes.

Expo generates native projects when needed. Keep generated `android/` and `ios/` folders out of source control; configure native behavior through Expo config and plugins unless this project intentionally moves to a prebuild/native workflow.

## Build an Android APK

EAS Build produces the installable Android APK in the Expo cloud using the `preview` profile:

```bash
eas build --platform android --profile preview
```
